## プロジェクトのテーマ（2026-11-03 キックオフのスライドより）

### #1：あなたにしかない深さを。
仕事や職場、生まれ育った土地、学んできた技術、とことんのめり込んできた趣味。あなたが一番よく知っている世界を出発点にしてください。今回つくるものを実際に使うのは、その世界であなたの隣にいる仲間や、同じ地域で暮らす人たち、そしてこれからそこを引き継いでいく人たちです。そこに、いま何が足りていないのか。その中に身を置いてきた人だからこそ気づける「足りないもの」を見つけてください。
- 方向性の例：ベテランの仕事のやり方を、本人が現場にいるうちに次の人が受け継げる形にする／自分の経験や感覚を、自由な発想で、まだ誰も見たことのない形にする／「そういうものだ」と誰もが諦めてきた日々の不便を、もう妥協しなくても良い便利なものにする

### #2：本来、誰にでも届くべきものを。
専門知識、費用、言語、手続き。さまざまな壁が、助けを受けられる人とそうでない人を分けています。多くの人を阻んできた壁を取り払い、一部の人にしか届いていないものを、届いていない人の手に。まずは壁の外側にいる具体的なひとりを思い浮かべてください。あるいは、高齢化や人手不足、災害への備えなど、日本社会がみんなで向き合う課題に、解決の一手を示してください。
- 方向性の例：専門家に頼れる人しか使えなかった手段を、必要な人なら誰でも使えるものにする／読めずに諦められてきた書類や案内を、誰にでも分かる言葉にする／人が減っていく地域でも、暮らしと備えを続けられる仕組みをつくる

### 見守りガジェットは #2 で出す
- **壁の外側にいる具体的なひとり**：スマホを持たず、Wi-Fiもない実家に住む自分の親
- **取り払う壁**：①スマホ（操作が分からない）②文字入力（LINEが打てない）③ネット回線（家にWi-Fiがない）。~~ボタンを押して話すだけ~~ → **（11/4変更）黒電話の受話器を取って話すだけ**、コンセントに挿すだけで越えられるようにする
- **届いていなかったもの**：家族とのLINEのやり取り、見守りサービス（既存のサービスはスマホかネット回線が前提）
- **社会課題**：高齢化と一人暮らし。実家が地方なら「人が減っていく地域でも暮らしを続けられる仕組み」にもつながる
- **語り方**：「LINEは誰でも使える、と思われている。でも、うちの親には届いていない。」のように、#2の文言（一部の人にしか届いていないものを、届いていない人の手に）をそのまま使う

## 方針変更：電話型のガジェット（2026-11-04）

- 母親は携帯電話を持たず、固定電話はある。本物の電話回線を使う方式（電話→LINE）も検討したが、家族→親の方向が弱く、見守りと写真ができず、電話番号の審査が締切に間に合わないおそれがあるため採らない
- 代わりに **電話の「形」を借りる**：古い黒電話（ダイヤル式）の中にPiを入れ、受話器を取って話す・聞く。家族のお便りは受話器を取ると流れる（留守番電話の方式）
- 押しボタン版を予備に残す。詳細は `仕様書.md`

## 決定：返信の受け口は Tailscale Funnel（2026-11-04）

- 家族のLINEの返信（Webhook）は **Tailscale Funnel** で受ける。無料で決まったURLになり、ドメインを買わずに済む。実家に置いたPiへMacからSSHで入る遠隔保守も兼ねる（SORACOM Napterの代わり）
- Cloudflare Tunnel＋独自ドメインは、製品版で自分のドメインにするときの候補として残す
- LINEのチャネルは11/4に作成済み。グループIDは最初に一度だけ、一時URL（trycloudflare）と `tools/capture_group_id.py` で取る
- **11/4 グループID取得済み**。1つのグループに入れる公式アカウントは1つだけ（ほかがいると join の直後に leave になる）。実家の家族グループに入れるときも先に確かめる
- **11/5 Tailscale Funnel の導入済み**。Piのtailnet上の名前は `koe-dayori`、Funnel は 443 → `127.0.0.1:8000`。LINE の Webhook URL を `https://koe-dayori.<tailnet>.ts.net/callback` に替え、「検証」が成功した。Mac も同じ tailnet に入れた（遠隔SSH用）
- 残り：管理画面で `koe-dayori` の鍵の期限切れを止める（Disable key expiry）。今のままだと 2027-05 に切れる

## 決定の変更：返信の受け口を Cloudflare Quick Tunnel に替える（2026-11-07、Pi で決定）

- **起きたこと**：本物の LINE の返信が Pi に届かなかった。LINE の Webhook の試験 API が毎回 `COULD_NOT_CONNECT`（`Session protocol negotiation failure`）を返した。LINE 側の受け口の設定は正しく、有効だった
- **切り分け**：Pi から Funnel の公開側（103.84.155.x）に curl すると、TLS 1.2 でも 1.3 でも、HTTP/1.1 でも HTTP/2 でも通る（署名なしで 403＝アプリまで届く）。証明書の検証も通る。同じ時刻に LINE の試験 API で両方を試すと、**Cloudflare Quick Tunnel は 200、Funnel は失敗**。アプリ側ではなく、Funnel の入り口と LINE の組み合わせの問題と確定した
- **原因の推測（未確定）**：Funnel が出している証明書は Let's Encrypt の新しい系列（中間 `YE2`・ルート `Root YE`、ECDSA、4段の連なり）で、2026-11-05 05:35 JST に発行されたもの。11/5 の検証は成功していたので、証明書が替わってから LINE が受け付けなくなった可能性がある。Funnel の証明書は Tailscale が自動で用意し、こちらで替えられない
- **替えたもの**：受け口は **Cloudflare Quick Tunnel（trycloudflare）**。アカウントもドメインも要らない（「ドメインは買わない」は守る）。Tailscale は遠隔SSH用にそのまま残す
- **URL が起動のたびに変わる問題**：`app/tunnel.py` が30秒ごとに cloudflared の窓口（`127.0.0.1:20241/quicktunnel`）から今の URL を聞き、LINE に登録してある URL と違えば LINE の API で書き換える。親は何もしなくてよい。cloudflared は `deploy/koe-tunnel.service` で動かす
- **この Wi-Fi で分かったこと**：IPv6 と QUIC（UDP）が外に出ないので、cloudflared は `--edge-ip-version 4 --protocol http2` に固定した
- **製品版**：Quick Tunnel は稼働の保証がない。製品版では Cloudflare の名前付きトンネル＋自分のドメイン、または SORACOM に置き換える
