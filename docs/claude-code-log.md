# Claude Code の使い方と試行錯誤の記録

審査の「Claudeの活用」「深さと実行力」で見せるための記録。日付順に追記する。

## 2026-11-04 LINEのグループIDを取る

- Pi上のClaude Codeが `tools/capture_group_id.py`（仮の受け口）を裏で動かし、LINEのAPI（`/v2/bot/info`、`/v2/bot/group/{id}/summary`）で、トークンとグループIDが正しいかを確かめた。鍵は画面に出さないようにした
- 外から入れるトンネル（cloudflared）を開く操作は、Claude Codeの自動モードに止められた。外への入口を開く操作は本人が動かす、という分担にした
- **つまずき**：公式アカウントを招待すると、join の直後に leave になる
  - 参加を許可する設定はオンになっていた（Official Account Manager と LINE Developers の両方で確認した）
  - Claude CodeがLINEの公式ドキュメントを調べ、「グループに同時に入れる公式アカウントは1つだけ」という制限を見つけた
  - テスト用グループに別の公式アカウントが入っていた。それを外したら参加できた
- 学んだこと：実家の家族グループに入れるときも、先にほかの公式アカウントがないか確かめる

## 2026-11-05 Tailscale Funnel を入れる

- インストール・ログイン・Funnel を開く操作は、`sudo` のパスワードと外への入口が関わるので、本人がSSHの画面で動かした。Claude Code は状態の確認（`tailscale status`、`tailscale funnel status`）と試しの送信を受け持った
- **つまずき**：LINE の「検証」が失敗し、受け口には何も届いていなかった
  - Claude Code が Pi から試すと届いていた。ところが Pi は MagicDNS で名前を tailnet の中のアドレス（100.x）に引いていて、外を通っていなかった
  - Google の公開DNS（DNS over HTTPS）で引くと、Tailscale の中継サーバー（103.84.155.x）に向いていた。`curl --resolve` で中継サーバーを通して試すと、届いた
  - もう一度検証したら成功した。Funnel を開いた直後で、外から名前を引けるようになる前に検証したためと考えられる（確かめてはいない）
- 学んだこと：tailnet の中のマシンから Funnel を試しても、外からの確認にはならない。中継サーバーを指定して試す

## 2026-11-05 話して送る流れ（WAV → 文字起こし → Claude → LINE）

- マイクがまだ届かないので、Open JTalk で合成した試しの声（近況・用件・体調不良の3つ）で流れを作った
- Pi 5 で faster-whisper の small と base を比べた（int8、CPU）。U14 の判断材料

| モデル | 10秒の録音にかかる時間 | 聞き間違いの例 |
|---|---|---|
| small | 約11〜12秒 | 柿→書き、台所→大どころ、送り迎え→お送り迎え |
| base | 約4秒 | いいお天気→良い予定期、庭→2話、トイレットペーパー→トイレットケーパー |

- base は3倍近く速いが、意味が崩れる。small を候補にした。本物の声で測り直す
- 「聞き取りにくい」の目印（avg_logprob < -1.0 または no_speech_prob > 0.6）は、どちらのモデルでも一度も立たなかった。合成音声だと、聞き間違えても自信が高く出るのではないか（推測。確かめていない）。本物の声で確かめ、基準を調整する
- Claude の呼び出しは、通信切れ（あとでやり直す）と、答えが使えない（安全側：緊急度は高、要約は文字起こしのまま）を分けた。送れなかったものは SQLite（WAL）に貯め、LINE の再送キーで二重送信を防ぐ

## 2026-11-07 Pi につながない間に、Mac でハードを使わない部分を作る

- Pi に入れない時間があったので、Mac の Claude Code が「ハードがなくても書けて、試せる部分」を受け持った。音と GPIO は差し替えられる形（`audio.Audio` と同じ形の偽物）にして、受話器の流れを Mac で試験できるようにした
- 作ったもの
  - 家族→親：LINE の受け口 `webhook.py`、お便りの貯め置き `inbox.py`、言い換え `agents/rewrite.py`、写真の説明 `agents/photo.py`（画像をそのまま Claude に渡す）
  - 受話器の流れ `phone.py`（留守番電話の方式）、フックスイッチ `hook.py`、読み上げ `tts.py`、音 `audio.py`・`sounds.py`
  - モニター表示 `display.py` と `static/display.html`、見守り `sensor.py`、今日の様子 `daily.py` と `agents/daily_check.py`、LINE への知らせ `notify.py`、全体 `main.py`
  - systemd（ユーザー単位）とキオスク表示 `deploy/`、試験 46件 `tests/`
  - Claude Code の **フック**（`.claude/hooks/check_secrets.py`）と **Skills** 3つ（`deploy-koe`、`try-letter`、`test-handset`）
- 試験で見つけて直したこと
  - 試験で「空いているポート（0）」を渡すと、0 が偽とみなされて本番の 8000 番を開いていた。警告（ResourceWarning）から気づいた
  - 送る途中で文字起こしが落ちたとき「あとでもう一度送ります」と言うと、録音はもう消えているので嘘になる。「もう一度お話しください」に分けた
  - 文字起こしは 1分の録音で 1分ほどかかる（11/5 の実測）。送る仕事を受話器の流れと別のスレッドにして、送っている間も次の受話器をすぐ取れるようにした（試験あり）
  - 試しのお便りを送る道具で、受け取った直後に準備のスレッドが動くと送り主が「ご家族」になる競合があった。名前を署名つきの試験用の項目で渡す形にした
  - フックが止めた理由を表示するとき、行の頭を出すと秘密の一部が Claude の記録に残る。何行目かだけを出すようにした
- 画面は Mac の Chrome（ヘッドレス）で3つの状態（新着・再生中・ふだん）を撮って確かめた
- Pi で確かめること：音のデバイス名、arecord の止め方（SIGINT で WAV の見出しが正しく書かれるか）、フックスイッチの向き、Open JTalk の辞書と声のパス、キオスク表示の自動起動

## 2026-11-07 夜 Pi で実機をつなぐ（Pi の Claude Code）

- **音のデバイス**：USB スピーカーフォン（`CONEXANT USB AUDIO`）と USB 音声アダプター（C-Media）を `.env` に `plughw:CARD=名前,DEV=0` で書いた。カード番号ではなく名前なので、挿す順が変わっても同じ機器を指す
  - **つまずき**：スピーカーフォンが `lsusb` にも `dmesg` にも出ない。Claude Code が「同じ端子でキーボードは見える → Pi は無事」「Mac では鳴る → 本体は無事」と順に切り分け、**充電専用のケーブル**だったと分かった
  - 受話器用アダプターのマイク端子には、まだマイクがない（録音の最大振幅 72＝無音）。スピーカーフォンのマイクなら 10977 で、文字起こしもできた
  - arecord を SIGINT で止めても WAV の見出しの長さが書き直されない（67108秒と出る）。faster-whisper は正しく 5.0 秒と読むので、今は困らない
- **話して送る → LINE**：スピーカーフォンで話し、文字起こし → Claude（要約・緊急度を並列）→ LINE まで本物で通った
- **LINE → 読み上げ → モニター**：本物の LINE の返信が Pi に届かなかった
  - LINE の Webhook 試験 API は `COULD_NOT_CONNECT`（`Session protocol negotiation failure`）。Pi の中から試すと tailnet の近道（100.x）を通って成功してしまい、気づくのが遅れた
  - 公開側の IP（103.84.155.x）に `--resolve` で当てると TLS 1.2/1.3・HTTP/1.1/2 とも通る。証明書は Let's Encrypt の新しい系列（YE2、ECDSA）で、11/5 05:35 JST 発行
  - LINE の試験 API は **endpoint を指定すれば設定を変えずに任意の URL を試せる**。同じ時刻に Funnel と Cloudflare Quick Tunnel を試し、Quick Tunnel だけ 200 → 受け口を替えた（README の決定の変更）
  - Quick Tunnel はこの Wi-Fi で QUIC（UDP）と IPv6 が外に出ず、`--edge-ip-version 4 --protocol http2` で通った
  - URL が起動のたびに変わるので `app/tunnel.py` を作り、30秒ごとに LINE に登録し直す。トンネルを起動し直して自動で書き換わり、LINE の試験 API で 200 を確かめた
  - **つまずき**：systemd で 5 秒おきに作り直したら trycloudflare が **429（作りすぎ）**。60秒おき・無制限にしたが、40分たっても解けなかったので夜は止めた
- **文字起こし 79.5秒 → 13秒**：無音の録音でも 32 秒かかることから、文字にする処理ではなく読み込みを疑った。部品の import は 0.3 秒、モデルの読み込みは手元からなら 1.8 秒、Hugging Face に問い合わせると 5 分以上待たされた（IPv6 が外に出ない Wi-Fi）。`local_files_only=True` と起動時の先読みにした
  - small と base を合成音声（16秒）で比べた：base は 4.6 秒だが「お母さん→おかわさん」「膝→日座」と聞き違える。見守りで体調の話を取り違えると困るので small のまま
- **Claude Code の自動モード**：systemd の自動起動（enable）は「ずっと残る仕組み」として止められ、本人が許可してから入れた。鍵（ANTHROPIC_API_KEY）は本人が nano で書き、Claude Code は `sk-` で始まる行があるかだけを数えて確かめた
- **フックスイッチ**：まだ配線していない（10分見張って GPIO17 は変化なし）

## 2026-11-08 朝 黒電話の改造：写真を見せながら Mac の Claude Code と配線する

- Pi の Claude Code から Mac の Claude Code へ、`docs/handoff-2026-11-07.md` で引き継いだ（本人が写真を見せながら相談したいため）
- 本人が中を開けた写真（全体・フックの下・受話器を置いた／上げた）を Mac に渡し、Claude Code が「白いT字の押し棒」と「その下の板ばね」がフックスイッチだと見分けた
- **つまずき**：板ばねは白いプラスチックの箱の中で、基板に直接はんだ付けされていて、線をつけるのが難しかった。基板の配線でトランスや抵抗につながっているので、ほかの部品を通って電気が回り込むおそれもあった
  - 電話機の中の板ばねにはんだ付けしない方法に切り替え、テスターで確かめてから GPIO17 と GND につないだ
  - Pi で GPIO17 を見張り、取る・置くを3回ずつ：1回の操作に1回だけ反応し、チャタリングはなかった。取ると pressed（`KOE_HOOK_PRESSED_IS_OFF_HOOK=1` のまま）
- **つまずき**：受話器を取ると「うまく送れませんでした」と言う。ログから、配線中に USB 音声アダプターが抜けていたとわかった（`Cannot get card index for Device`）
  - 同時に、プログラムの不具合が2つ見つかった。録音に失敗しても空の録音を送ろうとしていた。受話器から音が出せなくても、お便りを「聞いた」にしてしまう作りだった。どちらも直し、試験を3件足した
- マイク（C9767）は、Amazon ベーシックの 3.5mm ケーブルを切って、テスターで線を確かめた（白＝先端→マイクの＋、むき出しの束＝根元→−、緑＝中間は使わない）。机の上で録って受話器の耳で聞き、声が録れた
- **つまずき**：受話器を上げたまま本番を起動すると、「取った瞬間」がないので録音が始まらない（ログに警告が出る）。撮影では「起動してから取る」の順を守る
- 結果：**黒電話の受話器を取って話し、置くと、家族の LINE に要点が届いた**（実機で初めて全体が通った）
